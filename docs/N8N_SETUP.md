# n8n and Google Sheets Setup

The website owns registration, admin access, and attendance state. n8n connects
those events to Google Sheets and Meta messaging. Attendee registration is
public; event data, contact data, and attendance controls are admin-only.

## 1. Configure the app

Copy `.env.example` to `.env`, then set unique values for:

- `ADMIN_EMAIL`, `ADMIN_PASSWORD`, `ADMIN_SESSION_SECRET`
- `N8N_REGISTRATION_WEBHOOK_URL`
- `N8N_CONTACT_WEBHOOK_URL`
- `N8N_THANK_YOU_WEBHOOK_URL`
- `N8N_INBOUND_WEBHOOK_URL`
- `N8N_WEBHOOK_SECRET`
- `META_APP_SECRET`

Use the **production** webhook URLs generated by n8n. Keep `.env` private and
never put webhook URLs, Meta tokens, or Google credentials in frontend code.
The app sends `Authorization: Bearer <N8N_WEBHOOK_SECRET>` with every n8n
request; configure each n8n Webhook node to require matching Header Auth.

## 2. Create two private Google Sheets

Create one spreadsheet for **Registrations** and another for **Contacts**.
Add a header row to each and share each file with the Google identity used by
the n8n Google Sheets credential as an Editor. Share with the admin's Google
account as a Viewer if the sheets should be view-only for the admin. Do not
share either file with the public website or attendees.

Use the n8n Google Sheets credential to append rows. Suggested columns:

**Registrations:** registration ID, event ID, event title, attendee name,
email, phone, attendee count, WhatsApp opt-in, Instagram opt-in, attendance,
registered time.

**Contacts:** name, role, company, email, phone, Instagram, address, other,
added time.

## 3. Registration-to-Sheets workflow

Create a Webhook node using the URL in `N8N_REGISTRATION_WEBHOOK_URL`, method
POST, and Header Auth. Connect it to a Google Sheets Append Row node targeting
the Registrations spreadsheet. Switch on `type`: append a row for
`registration.created`; find and update the matching registration ID for
`registration.attendance_updated`. Map the nested `registration` fields plus
the event title and ID from the incoming `event` object. Add an IF node before
any WhatsApp confirmation message and require
`registration.consentWhatsApp` to be true.

The incoming payload has this shape:

```json
{
  "type": "registration.created",
  "event": { "id": "...", "title": "..." },
  "registration": {
    "id": "...",
    "fullName": "...",
    "email": "...",
    "phone": "...",
    "attendeeCount": 1,
    "consentWhatsApp": true,
    "attendance": "registered"
  },
  "sentAt": "..."
}
```

## 4. Card-scan-to-Sheets workflow

Create a Webhook node using `N8N_CONTACT_WEBHOOK_URL`, method POST, and Header
Auth. Append the `contact` fields to the Contacts spreadsheet. OCR runs in the
admin's browser; the admin reviews the extracted values and clicks **Save
contact** before they are stored and sent to n8n.

## 5. WhatsApp and Instagram replies

Create a Webhook node using `N8N_INBOUND_WEBHOOK_URL`, method POST, and Header
Auth. Add a Switch node on `platform` and connect each branch to its matching
Meta messaging credential. Use the message text to match your approved FAQ
answers, then reply to `senderId`. The payload includes `messageId`, `text`,
`senderId`, `platform`, and the available phone/account ID.

In Meta, point the WhatsApp and Instagram webhooks at the app's public HTTPS
URLs:

- `https://YOUR_DOMAIN/webhook/whatsapp`
- `https://YOUR_DOMAIN/webhook/instagram`

Set their verify tokens in `.env`. In the Meta app, subscribe to the required
message events and use a WhatsApp Business number plus an Instagram
Professional account. `META_APP_SECRET` must contain the Meta app secret; the
server verifies `X-Hub-Signature-256` against the raw request body and rejects
unsigned webhook posts. Meta app review and permission approval are required.

## 6. Attendance thank-you workflow

The admin marks attendance in the Registrations tab, chooses an event, then
explicitly starts the thank-you workflow. The app sends only attendees marked
present with `consentWhatsApp: true` to `N8N_THANK_YOU_WEBHOOK_URL`. Append or
update the matching registration rows in Sheets, then send the approved
WhatsApp thank-you template. Include each registration ID as the n8n
idempotency key and do not remove the consent filter. The admin action is
marked requested once n8n accepts the webhook; n8n must alert on downstream
Meta delivery failures.

WhatsApp generally requires an approved template when messaging outside its
customer-service window. Instagram does not permit arbitrary messages to a
public username: outbound DMs require an eligible existing conversation and
the recipient-scoped Instagram ID. This app currently routes incoming
Instagram questions for replies, but does not send post-event Instagram DMs.

## 7. Test and activate

1. Start n8n and activate each workflow; use production webhook URLs.
2. Add the URLs and shared secret to the app's `.env`, then restart Node.
3. Sign in to `/admin` and check the **Automations** tab. It reports
   whether each URL and the shared secret are configured, never their values.
4. Create a draft event, publish it, and submit a test registration at
   `/events.html`. Confirm the local registration and Sheets row.
5. Scan a test card and save it; confirm the Contacts sheet row.
6. Mark the test attendee present and test the thank-you workflow only with a
   number you control and explicit WhatsApp consent.
7. Configure the Meta webhook URLs and verify tokens only after the server is
   deployed at a public HTTPS address.

The app saves its local record before calling n8n. If a webhook is down, the
registration/contact remains locally stored but delivery needs to be retried
from the relevant workflow. Thank-you requests are not resent after n8n accepts
them; use n8n error handling to retry downstream failures without duplicating
delivered messages. Add an n8n error workflow and alerting before relying on
these automations in production.
